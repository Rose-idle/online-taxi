二、订单状态机（OrderConstants）

1订单开始乘客下单
➜
2司机接单派单匹配
➜
3去接乘客to-pick-up
➜
4到达起点arrived-departure
➜
5乘客上车开始计费行程
➜
6到达目的地算里程/时长/车费
➜
7发起收款push-pay-info
➜
8支付完成订单闭环
0 订单无效：派单循环 6 次（每次间隔 20s）均未匹配到司机
9 订单取消：按操作方（乘客1/司机2）+ 当前状态判定「提前取消 / 违约取消」（接单后超过 1 分钟即违约）
派单核心：以上车点为中心，按 2km → 4km → 5km 半径用高德周边搜索空闲车辆；对每辆车查「绑定司机 + 是否出车中 + 车型是否匹配」，用 Redisson 对 driverId 加锁，校验司机无进行中订单后落单，并 SSE 同时推送司机（新订单详情）与乘客（车牌 / 车型 / 司机位置）。

三、关键业务规则速查

环节规则 / 要点
登录鉴权手机号 + 验证码 → 签发 JWT（identity：1=乘客，2=司机），API 层 JwtInterceptor 校验
预估价格高德 direction 取距离(米)/时长(秒) → 读 price_rule 最新版本 → 起步价 + 超起步里程费 + 时长费
下单前置校验城市有司机 · 计价规则为最新版本 · 城市已开通服务 · 乘客无进行中订单
计费公式起步价 + max(0, 里程-起步里程)×单价/km + 时长(分)×单价/分，四舍五入 2 位
行程结束调高德 trsearch 轨迹查询得实际 driveMile / driveTime，再算实际价格
